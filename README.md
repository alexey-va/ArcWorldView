# ArcWorldView

Живой трёхмерный просмотр выбранных мест Minecraft в браузере: спавн,
поселения ArcCivs, игроки, открытые NPC и животные. Ортографическая камера,
масштабирование и поворот. В RusCrafting открывается вкладкой «Живой мир»
по адресу `/world`; приложение работает под `/worldview/`.

## Сервер

Paper 1.21.11, Java 25, ArcCore **0.1.25** или новее. Поселения и их
пакетные жители появляются при установленном ArcCivs **0.1.97** или новее.
Нативные сущности Paper не требуют ArcCivs. Невидимые игроки, spectator и
игроки с metadata `vanished` не публикуются. Инвентари и чат не передаются. Публичные декоративные дисплеи лутбоксов
экспортируются только их владельцем ArcExcellentCrates; частные превью в этот
источник не входят. Браузер проигрывает ограниченные будущие позы локально,
без повышения частоты серверных снимков.

В `plugins/ArcWorldView/config.yml` задаются разрешённые места и вертикальное
окно. Автоматическое обнаружение поселений дополняет список. Нельзя запросить
произвольный мир или координаты через HTTP. Высота окна — 16–256 блоков,
кратна 16; нижняя граница может быть любым целым числом.

HTTP слушает **127.0.0.1:25912**. Внешняя публикация идёт через TLS-прокси;
конфигурации nginx и отдельного SSH-туннеля находятся в репозитории сайта
`ruscrafting-website/deploy`. API допускает только GET и HEAD.

Захват использует уже загруженные чанки: плагин не загружает, не генерирует
и не удерживает их. Все зрители одного места читают общий снимок. Общий
лимит Main — 1,5 мс за тик, один снимок чанка и 96 нативных выборок Bukkit; активны
не более двух мест. Копирование одного `ChunkSnapshot` и получение массива
сущностей чанка — неделимые вызовы Paper, поэтому лимит проверяется между
вызовами и не прерывает уже начавшийся вызов. Снимки публичных пакетных NPC
получаются через отдельный ограниченный источник Core (до 512 записей);
его синхронный вызов также нельзя прервать внутри исполнения.

Палитры, RLE, JSON, gzip, проверка файлов и HTTP работают вне Main;
геометрия и изображение строятся в браузере. Очереди, кэши и число сущностей
ограничены. Неактивные места перестают обновляться. Состояние наблюдения
не сохраняется в базу; каждый запуск имеет отдельное поколение кэша.
Протокол описан в [WIRE.md](WIRE.md).

## Сборка

Зависимости Core разрешаются из публичного Maven RusCrafting. Нужные общие
renderer helpers входят в исходники с закреплённой ревизией и хэшами;
доступ к закрытому репозиторию операций для сборки не требуется:

```sh
cd web
npm ci
npm run build
npm test
cd ..
./gradlew --no-daemon test shadowJar
python3 scripts/verify-jar.py --arc-core-jar /absolute/path/to/ArcCore-0.1.25.jar
```

JAR включает браузерный JavaScript и шрифты. Текстуры Minecraft и серверный
ресурспак в Git и JAR не включаются: генератор подготавливает отдельный
каталог ресурсов с manifest, хэшами файлов и неизменяемой ревизией. Его
устанавливают в `plugins/ArcWorldView/assets`; `current.json` выбирает ревизию.
Отсутствующий или неверный manifest останавливает запуск просмотрщика.

## Жизненный цикл

Плагин использует owned lifecycle Core: таймер, подписки, нативные ссылки,
HTTP listener, исполнители и HTTP-клиент скинов закрываются при остановке.
Поздние асинхронные результаты не публикуются в новое поколение. Команда
`/worldview` показывает администратору состояние и ссылку; она не меняет мир.

Обновление общей API/provider части **ArcCore** требует обычного согласованного
рестарта сервера. Проверенная сборка, поставка файлов, активация и наблюдение
в живом браузере подтверждаются отдельно.
